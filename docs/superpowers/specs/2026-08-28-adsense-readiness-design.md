# 애드센스 신청 준비 — 설계

날짜: 2026-08-28
상태: 승인됨 (구현 대기)

## 배경

기존 blogger_auto 시스템(주식/건강/맛집, 하루 5개+, 트렌드+에버그린 자동발행)에 애드센스를 붙이고 싶다는 요청. 그러나 구글은 "대량 생성 저품질 AI 콘텐츠(scaled content abuse)"를 애드센스 승인 거부/검색 페널티 대상으로 명시함. 판별 기준은 문체가 AI 같은지가 아니라 **발행 속도 대비 도메인 신뢰도, 주제 폭, 콘텐츠 깊이/독창성** 같은 행동·품질 패턴임.

이 스펙은 "AI 티 감추기" 같은 탐지 회피가 아니라, 실제 리스크 요인(신생 도메인 + 여러 무관 주제 + 얇은 콘텐츠 + 사람 검토 없음)을 하나씩 줄이는 방향으로 설계함.

## 확정 사항

### 1. 주제 범위 축소 (`keywords.py`)
- `EVERGREEN_KEYWORDS`에서 "맛집" 제거, 재테크·건강 2개 니치만 유지
- 나중에 주제를 넓히고 싶으면 딕셔너리에 항목 추가 — 별도 토글/설정 없음 (YAGNI, 필요할 때 요청하면 바로 반영)

### 2. 트렌드 키워드를 니치 안으로 한정
- 현재 `get_trend_keywords()`는 `pytrends.trending_searches(pn="south_korea")`로 한국 전체 실시간 트렌드(연예인/스포츠 등 무관 주제 포함)를 그대로 가져옴
- EVERGREEN_KEYWORDS의 각 니치 키워드를 시드로 `pytrends.related_queries()`(rising)를 호출해, 재테크/건강 관련 상승 검색어만 수집하도록 교체
- 시드 API 실패 시 기존처럼 evergreen만 사용하는 폴백 유지

### 3. 발행 개수 기본값 하향
- `config.json` 최초 생성 시 기본값 5 → **3**
- 텔레그램 `/count` 명령으로 언제든 조절 가능한 기존 동작은 유지

### 4. 콘텐츠 품질 프롬프트 강화 (`generator.py`)
- 구조: 도입(문제 공감 1문단) → 본론 소제목(h2) 2~3개, **각 소제목마다 구체적 방법/수치/예시 최소 1개** → 마무리(요약 + 다음 행동 제안)
- 숫자 지어내기 금지 규칙은 유지하되 "두루뭉술한 설명" 대신 "실행 가능한 구체적 팁"으로 대체하라는 지시 추가
- 문장 리듬 지시 추가: 같은 어미/문장 시작 반복 금지, 문장 길이 다양화
- 재테크 글: "투자 조언이 아닌 일반 정보, 투자 판단은 본인 책임" 면책 문단 자동 포함
- 건강 글: "의료 전문가 상담을 권장" 면책 문단 자동 포함
- 응답 JSON에 `summary`(1~2문장 메타 설명용) 필드 추가

### 5. 최소 분량 상향 (`validate.py`)
- `MIN_LENGTH` 200 → **2000**

### 6. 메타 설명 반영 (`post.py`)
- Blogger Posts API의 `searchDescription` 필드에 generator의 `summary` 값을 채워 검색 스니펫에 노출되게 함

### 7. 필수 페이지 자동 생성 (신규)
- 개인정보처리방침 / 소개 / 연락처 3개 페이지를 Blogger Pages API(`service.pages().insert()`)로 생성하는 일회성 스크립트
- 애드센스 심사에서 요구하는 필수 정적 페이지

### 8. 애드센스 신청 절차 문서화 (`SETUP.md`)
- 신청 전 체크리스트(글 최소 개수, 필수 페이지 존재 여부 등)
- 신청 절차(계정 생성 → 사이트 등록 → 심사 대기)
- 승인 후 실제 광고 게재까지: ads.txt 파일을 블로그 루트에 배치하는 법, Blogger "수익" 탭 연결법

## 범위 밖 (일부러 안 만듦)

- "보수모드 자동전환" 같은 config 토글: 신청 기간엔 보수적으로, 승인 후 자유화하는 흐름은 맞지만 이걸 코드로 자동화할 이유가 없음. 나중에 주제/개수를 넓히고 싶을 때 그때 요청하면 코드 몇 줄 수정으로 충분함
- AI 생성 티를 안 나게 하는 탐지회피 기법: 실제 리스크(콘텐츠 깊이·주제 일관성·발행 속도)를 안 건드리고 표면적 문체만 바꾸는 방식이라 효과가 없고, 애드센스 퍼블리셔 정책의 "기만적 콘텐츠" 조항과 충돌할 소지가 있어 배제. 대신 4번(실제 품질 개선)으로 대체
